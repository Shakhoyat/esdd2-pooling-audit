# Inapplicable components in audio anti-spoofing — reproduction code

## What the paper claims

Component-level anti-spoofing scores a recording's speech and its environment on separate axes. An
untouched capture has no separable component, so both attributes are inapplicable, yet the ESDD2
protocol counts such clips as bona fide on both axes. The paper shows that this stated rule breaks
the equal error rate it reports. Pooling the inapplicable clips mixes ROC curves: areas survive, and
the EER admits no aggregation rule (Theorem 1). A published pooled EER therefore leaves the
component-only EER in an interval (Theorem 2), and on ESDD2 those intervals separate none of the 55
published comparisons. No per-clip score reduction repairs this (Proposition 3); training on the
stated rule lowers the reported EER without improving component detection. The organiser already
holds the partition, so the fix is a one-line change in the scorer.

## Claim → script → test

Every numeric literal is listed in `paper_numbers.yaml` with its location, printed precision and the
value that reproduces it. The values there are **transcribed by hand from the LaTeX source**, not
generated by this code, so the check is not circular.

entries against the committed `results/`, so it runs without any data; `results/MANIFEST.json`
records the inputs those results were built from.

## Sixty-second quickstart

On a clean checkout, with nothing downloaded:

```bash
pip install -r requirements.txt
make test          # the paper's numbers against committed results, plus unit tests
```

To recompute from per-clip scores rather than trust the committed results:

```bash
python tools/fetch_data.py --labels-only      # 2.4 MB; accept the CompSpoofV2 licence first
make verify                                   # about three minutes on CPU
```

`make all` regenerates `results/`: every number, Table 1 and Table 2 as `.tex` rows, and Figure 1.
`make gate` checks submission readiness over `paper/main.tex`.

## Data acquisition

**Tier 0 needs no audio.** CompSpoofV2 publishes `eval_label.csv` as a standalone file, and this
repository ships the two small derived files that would otherwise need the large archives.

| what | size | where from | unlocks |
|---|---|---|---|
| `eval_label.csv` | 2.4 MB | CompSpoofV2 on Hugging Face | every EER, both tables' point estimates, §2, §3, §4.3, §4.5, Figure 1 |
| `data/derived/clusters.csv` | 1.4 MB | **shipped** | the clustered bootstrap intervals |
| `data/derived/native_format.csv` | 1.3 MB | **shipped** | §4.4's format-matched numbers |
| `baseline_scores.txt` | — | ESDD2 baseline repository | the reference system |
| `development.tar.gz` | 88 GB | CompSpoofV2 | only the 175,361 and 24,864 clip counts |

With `eval_label.csv` and the shipped files, every entry verifies except those two counts: their
CSVs are 46 MB inside an 88 GB split archive that cannot be partially extracted. `verify.py` reports
any entry whose input is absent as not checked, with the reason, rather than passing it.

`clusters.csv` holds **anonymous cluster integers** — no source file, corpus or generator names —
and `native_format.csv` a sample rate and channel count per clip. Regenerate both from the archives
with `tools/derive_metadata.py` and compare against the sha256 in `MANIFEST.sha256`.
See `data/README.md` for the full terms.

## What this repository does not contain

- **No audio and no corpus files.** CompSpoofV2 is CC BY-NC 4.0 and access-gated; fetch it yourself.
- **No ESDD2 baseline code.** It is CC BY-NC 4.0; `src/pooling_audit/eer.py` is a reimplementation
  from its published description, citing the original file. The one behaviour it must preserve is
  that the reported EER is the *mean* of FAR and FRR at the nearest ROC vertex, which is what makes
  the reported value a step function of the fill constant.
- **No baseline `prediction.txt`.** It ships with the baseline repository.
- **No encoder weights.** `models/fetch_encoders.py` downloads and hash-verifies them.
- **No probe checkpoints.** They were never retained; see Roadmap.
- **No `spconf.sty`.** The ICASSP style file carries no licence statement; get it from the author kit.
- **None of the authors' internal notes.** `paper/main.tex` has every comment's text removed.

## A numerical check is not a proof

Theorems 1 and 2 and Proposition 3 are proved in the paper. This repository does something weaker,
and it matters which is which.

- `tests/test_identities.py` shows identities (1) and (2) hold to machine precision on synthetic
  data: a check that the premise is implemented correctly, not a proof of it.
- `test_no_aggregation_rule_exists_for_the_crossing` builds two component pairs with identical
  component crossings and different pooled crossings. That is a genuine counterexample, and it does
  establish that no rule φ(T₀, Tₐ, w₀) exists for the crossing.
- `tests/test_bounds.py` checks the interval formula and the ordering criterion as arithmetic.
  Sharpness — that every point of the interval is attained — is not established here.

## Paper gate

`make gate` runs `tests/test_paper_hygiene.py` over `paper/main.tex`: no surviving `TODO`, no
"development" (an earlier draft mislabelled the evaluation split), every citation resolving both
ways, and a compiled PDF of at most 5 pages with references alone on page 5. The page checks need a
compiled PDF: set `ESDD2_PAPER_PDF`, or place `spconf.sty` in `paper/`.

**The gate currently fails on the page budget**, which is a true statement about the paper, not a
defect in the gate. It is kept out of `make test` because it is a release condition rather than a
correctness test.

The trainers are **ports, not rewrites**: structure and every hyper-parameter come from the scripts
that produced the paper's scores. Absolute paths are gone, and all settings are read from
`configs/systems.yaml`, which `verify.py` also checks the paper's layer and sampling-rate references
against.

## Pre-registration

The consistency experiment of §4.3 was pre-registered before the runs, in commit `8694d0c` of the
authors' working repository. **That repository is private** — it holds reviewer correspondence and
draft material — so the timestamp cannot be inspected from here. The per-clip scores of both arms
ship in `scores/consistency/`, so the experiment's four reported numbers verify in tier 0 without it.

## Checkpoints were not retained

The probes were trained and their per-clip scores saved; the weights were not. Tier 1 regenerates
the probes from frozen encoder features rather than restoring the originals, and because training is
seeded and the recipe pinned, a rerun should land in the same place without being bit-identical.
**A full retraining has not been re-run since the training-split feature cache was lost**, so tier 1
is smoke-tested, not reproduced; `scripts/train/README.md` lists exactly which entry points that
covers.

## Roadmap

- **Full tier-1 retrain, after submission.** Rebuild the training-split features from the corpus
  audio and rerun all three seeds.
- **Probe checkpoints, after that retrain,** published alongside the scores under CC BY-NC 4.0.

Neither affects what the paper claims: every published number is verified in tier 0 against the
per-clip scores that produced it.
