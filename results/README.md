# `results/`

Everything in this directory is a build artifact, regenerated by `make all`
(`scripts/make_results.py`) from the raw per-clip scores in `scores/` and `data/`. Do not
hand-edit any file here; edits are silently lost the next time the pipeline runs. Committed
copies exist so a clean clone has something to compare a fresh run against
(`tools/manifest.py --check`).

## `artefacts.json`, key `t2`

This key holds an **older, superseded convention** for the predicted-applicability EER,
alongside the current one used elsewhere. Specifically `t2.env.cond`, `t2.speech.cond`,
`t2.env.err_cond`, `t2.speech.err_cond`, and `t2.speech.reduction_pct` compute the EER on the
gated-selected rows **without** counting the gated-in structural zeros as positives (no
`include_inapplicable=True`; see the comment at `src/pooling_audit/recompute.py`'s `table2()`,
the `cond = ...` line). That gives 0.2022/0.1886 (errors 0.0068/0.0019, 78% speech reduction).

**The paper's actually-printed numbers (0.2028/0.1892, errors 0.0062/0.0013) come from a different
function**, `acds_gate()`'s `eer_gated` in `src/pooling_audit/acds_artefacts.py`, which *does*
count the gated-in structural zeros as positives -- matching the paper's own stated convention
("counting, as a scorer without the labels must, the structural zeros the gate admits").

Both functions are correct for what they compute; they are not interchangeable, and neither is
wrong on its own terms. `table2()`'s `cond`/`err_cond` fields are kept because
`tests/test_claims.py` and the pre-existing `verify.py` pin against them for regression-testing
purposes (they faithfully reproduce an earlier draft's numbers), not because they're the
convention to cite for anything new. Full trace: `verify/VERIFICATION_REPORT.md`, "Investigative
findings."

`t2.threshold_sweep` is the same older convention swept over `gamma` thresholds 0.1-0.9. It is not
printed anywhere in the submitted paper.
